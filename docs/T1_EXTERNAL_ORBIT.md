# Optional T1 two-body numerical cross-check

The [external-orbit audit](../artifacts/t1-external-orbit-audit.json) numerically integrates the heliocentric, planar two-body equation for all nine T1 fixture cases and one case using rounded axes from the [NASA fact-sheet snapshot](T1_NASA_PARAMETER_SENSITIVITY.md). It uses the separately pinned SciPy 1.18.1 `solve_ivp` DOP853 installation described in [the T3 solver provenance note](T3_EXTERNAL_SOLVER.md). SciPy and NumPy are optional and are not core or wheel dependencies. The environment verifier checks exact package versions, the Windows wheel hashes in `requirements-t3-scipy-win-py312.txt`, and installed license-notice hashes.

For each outward transfer, set length scale $L=r_1$, time scale $T=\sqrt{r_1^3/\mu}$, and dimensionless departure state $(x,y,v_x,v_y)=(1,0,0,\sqrt{2-1/a})$ with $a=(1+r_2/r_1)/2$. DOP853 solves $\ddot{\boldsymbol r}=-\boldsymbol r/|\boldsymbol r|^3$. A terminal event detects the **outward-to-inward** zero crossing of $\boldsymbol r\cdot\boldsymbol v$, so the solver is not given the analytic transfer time. The recorded event time, final Cartesian state, specific energy, and angular momentum are compared with the two-body Hohmann reference. The analytic vis-viva departure speed is still supplied as the initial condition: this is an independent time-propagation check, not an independent derivation of the entire transfer model.

The predeclared gates require ten detected apoapses and at most $10^{-9}$ relative error for time, final position, final velocity, maximum specific-energy drift, and maximum angular-momentum drift. The largest measured relative time difference was $7.73\times10^{-12}$; the largest final-position difference was $1.42\times10^{-11}$. A repulsive-gravity negative control finds no outward-to-inward apoapsis in its finite integration window. This control tests the detector and force direction within that window, not a global theorem about repulsive orbits.

Run `python scripts/verify_t1_external_orbit.py --verify` **in the pinned SciPy environment** to recompute every case and compare the complete result, source fingerprints, and environment with the committed audit. The core `scripts/verify_acceptance.py` performs only a static fingerprint, input, threshold, and boundary check of this optional audit; it deliberately does not import SciPy or claim a dynamic external-solver rerun. This distinction is recorded in `artifacts/acceptance-verification.json`.

The [optional shared Run](../artifacts/t1-external-run-audit.json) binds the same dynamic receipt to a registered Tool, versioned SciPy Provider, offline Policy, Agent, Memory, Evaluator, append-only Events, Trace, unverified Claim, source and license fingerprints, and a portable replay manifest. Run `python scripts/verify_t1_external_orbit_run.py --verify` in the pinned SciPy environment to recompute the solver, replay the Run after relocation, and check that altered result and license bytes fail. The core acceptance command checks this optional Run's saved hashes and boundaries without loading SciPy. ToolRegistry enforces declared calls, providers, and paths; it is not an operating-system sandbox or an interruptible timeout for code already running inside a handler. The core T1 CLI Run remains analytic.

All nine benchmark cases are synthetic. The tenth uses only rounded NASA fact-sheet axes while retaining the synthetic fixture's solar $\mu$; the fact-sheet snapshot has unresolved page-specific rights and lacks offline authentication of the original full pages. Neither case family uses a dated ephemeris, launch window, non-circular planetary orbit, perturbing bodies, or a Lambert mission solution. The audit and optional Run do not establish real-data, mission, broad scientific-validity, or publication claims.
